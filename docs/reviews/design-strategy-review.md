Review date: 6 September 2026. Read-only strategy review of `/home/vilius/projects/5min-btc-polymarket/.worktrees/standalone/docs/design.md` and `docs/plans/standalone.md` before implementation. No repository files were changed.

**Verdict: proceed after the bounded specification corrections below.** The proposed scope is appropriate for a small live experiment. It correctly uses raw spot volatility, distinguishes the settlement model from stopped-policy profit, avoids claiming that scenario stresses are confidence intervals, and does not require a large simulator or fitted model before a bounded experiment. I found no reason to replace the chosen strategy architecture or add machine learning. Findings are specification gaps to resolve before workers make inconsistent assumptions, rather than claims that unimplemented code is already broken.

1. **[P2] Condition the probability on the spot observation's time, separately from the entry clock.** Locations: `docs/design.md:50–54,73–77`; `docs/plans/standalone.md:113–120`. The probability formula uses an unspecified `tau`, while the design permits a raw-price observation up to five seconds old. If the last observed spot is at `t_s` and the order decision is at `t_now`, conditioning on that price requires `model_tau=T−t_s`, not `T−t_now`. Under the stated zero-drift Brownian approximation, the unobserved price movement since `t_s` adds variance. Using decision-time tau treats stale spot as contemporaneous and can overstate a favourite's probability. Correction: carry `entry_tau=T−t_now` for the 60..180-second entry gate and `model_tau=T−spot.timestamp` for the model. Use a coherent history as of the last accepted price and log both horizons. Add a numerical test showing an otherwise identical older observation moves the central probability toward 0.5. Revalidate the entry time immediately before submission, or state a small submission buffer, so evaluating at exactly 60 seconds does not authorize an order entering after the claimed cutoff. This does not require modelling the final averaging minute for new entries.

2. **[P2] Make sell-fee allowance, price-band semantics and liquidation triggers deterministic.** Locations: `docs/design.md:65–70,83–94`; `docs/plans/standalone.md:123–127`. The proposed entry metric subtracts estimated buy/sell fees but does not specify the assumed exit price. The later policy can sell at a take-profit, a stop, a time exit, or a worse partial-fill price. An estimate using the buy price for the sell fee can underreserve when the exit moves toward 0.5. Correction: for the current `0.07*p*(1−p)` schedule use a documented worst-case sell-fee reserve of `0.0175/share`, or an explicitly defined alternative derived from the actual permitted fee schema. Report the components separately and continue calling the result a terminal surplus proxy with a cost reserve. For entry, apply the maximum ask band to the signed buy limit, use fees across the consumed levels, and size against the final rounded quantity and reservation. Define the stop/take-profit trigger on the depth-weighted executable proceeds for actual held shares; a tiny top bid at 0.98 should not imply that the position can realize that price. For insufficient full depth, specify partial-close handling rather than inventing a full liquidation quote. These are calculation definitions, not requests to optimize the chosen stop levels.

3. **[P2] Distinguish a daily/session loss budget from a stop-trading threshold.** Locations: `docs/design.md:81–87,125–142`; `docs/plans/standalone.md:172–178`. The design reserves trade principal, but does not explicitly say whether a new trade's maximum loss must fit the remaining daily/session loss allowance. With $9 of realized losses, a $10 threshold check alone still admits a new $5 position; if its stop cannot execute, loss can reach $14. Correction: preferably require `loss_already_consumed + maximum_unresolved_loss + new_order_reservation <= configured_loss_budget`, independently for the daily and session budgets. Define when resolved losing residual shares consume the loss budget even though no sell receipt occurs. Distinguish locked claimable winners from available cash, as the design already intends. Alternatively, explicitly call $10 a threshold for stopping new entries rather than a maximum loss, but do not mix those meanings in configuration or docs. Include the $9-plus-$5 case in a risk test. No change to the outer $100 allocation is required.

4. **[P2] Define the comparison so it can identify what improved.** Locations: `docs/design.md:17–28,50–71,172–178`; `docs/plans/standalone.md:123–126,192–211`. The plan calls momentum the original/reference rule, although its `.70–.95` band and 90..150-second window differ from the supplied `.80–.99` rule near 120 seconds. The value candidate simultaneously changes price band, time window and selection model. A better live result would therefore test a bundled strategy, not isolate the probability model's contribution. Also, recording decisions alone does not explicitly ensure an auditable observation for both candidates in the same round. Correction: label the chosen momentum defaults a modified reference, or preserve a literal legacy configuration as a named comparison. During observe/live collection, evaluate both configured candidates against the same available snapshots and record each candidate's first eligible intent per round without manufacturing fills or hypothetical PnL. Define one fixed 120-second calibration observation per round, selected without looking ahead, with timing tolerance and missing-observation reason. State that actual live execution tests the chosen candidate only, while the other records support signal/selection comparison. This is a small measurement addition, not a simulator or an A/B trading platform.

5. **[P2] Specify what constitutes clean five-second volatility history.** Locations: `docs/design.md:45–63`; `docs/plans/standalone.md:119–120,139–143`. Clean warm-up, gap invalidation and effective counts are sensible requirements, but the sampling and gap rule are not specified precisely enough for independent strategy/data workers. An implementation could forward-fill stale values on the five-second grid and count the artificial zero returns as observed quiet trading. A test rejecting a 61-second gap would not catch that. Correction: state the source-time sampling rule, the maximum age of an observation used at a grid point, and the maximum acceptable gap between valid sampled observations. Record missing grid points explicitly and never count carried-forward stale points as new independent observations. Derive elapsed time and counts from accepted observations, reset the affected warm-up when the configured coverage requirement fails, and add a fixture with a shorter missing segment that would otherwise masquerade as low volatility. The numerical gap tolerance can be a documented experiment default; it does not need to be learned from a large dataset.

The core formula `sigma²*(tau−40)` is correct before a verified ending 60-second arithmetic averaging window under the stated raw-price Brownian model. The $90 lead / $50 one-minute standard deviation / 120-second example gives approximately 0.940484. The opening reference is properly conditioned as a known observed value, rather than assigned a second independent forecast variance. The remaining mathematical limitation is already identified accurately: matching a TWAP60 feed name does not by itself prove every discrete sampling/boundary convention. The planned anonymous probe should establish that convention before enabling captured-anchor use; failure should remain an explicit unsupported-contract condition rather than be hidden by the USD10 scenario.

The USD10 reference stress, 1.25 volatility stress, two-cent margin, price bands and exit levels are acceptable transparent hypotheses for this experiment. They are not empirically optimized values or statistical guarantees. The review does not recommend changing them merely to create more trades. Preserve the explicit `terminal_surplus_proxy` label and the actual realized exit/fee measurements throughout implementation and final reporting.
